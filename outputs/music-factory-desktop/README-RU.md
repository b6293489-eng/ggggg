# Music Factory 2.2.3

Локальная ферма для macOS Apple Silicon и Windows x64: JSON-план → генерация WAV через ACE-Step 1.5 → распределение между аккаунтами → публичная пакетная загрузка в SoundCloud → отдельная подача на монетизацию.

## Запуск

- macOS: открой `releases/v2.2.3/Music Factory-darwin-arm64/Music Factory.app`.
- Windows: распакуй ZIP полностью и открой `Music Factory.exe`. Не запускай EXE внутри ZIP.
- Для пульта не нужны отдельно установленные Node.js или Python. ACE-Step и его модели устанавливаются отдельно.
- Для публикации нужен установленный Google Chrome. Расширение Chrome больше не используется.

Данные хранятся вне папки программы. Обновление приложения не удаляет библиотеку, WAV и очередь.

## Один раз войти в три аккаунта

Открой в Factory раздел «Аккаунты» и для каждой карточки выполни:

1. «Войти в SoundCloud» → «Открыть браузер Factory». Для входа откроется обычный Chrome без Playwright, поэтому Google не должен показывать предупреждение о небезопасном браузере.
2. Самостоятельно введи пароль и код подтверждения, затем полностью закрой это отдельное окно Chrome.
3. Вернись в Factory и нажми «Проверить вход» — Playwright проверит профиль скрыто, без второго окна браузера.

Проверка открывает `soundcloud.com/upload`, находит внутренний загрузчик `/n/upload` и поле выбора файлов, но не передаёт аудио и ничего не публикует. После успешной проверки окно закрывается, а cookies остаются в отдельном постоянном профиле Playwright.

Соответствие профилей:

- Бос → `@bos-423483424`
- Gleb fps / Gleb Ohai → `@nn1v-680019554`
- Rivi / Boner → `@rivi-135338423`

Обычные профили Chrome не используются и не закрываются. На новом компьютере вход нужно выполнить заново: cookies и пароли не входят в резервную копию.

## Публикация

Публикацию запускает только пользователь кнопкой в Factory. Для каждого аккаунта приложение использует его отдельный проверенный профиль и выполняет один пакетный альбом:

1. открывает страницу Upload и внутренний iframe `/n/upload`;
2. передаёт только WAV выбранного аккаунта;
3. заполняет `Album title`;
4. выбирает `Public`;
5. нажимает `Amplify tracks` и ждёт подтверждение анализа;
6. один раз нажимает нижнюю зелёную `Upload`;
7. ждёт завершения и пытается сохранить публичные ссылки.

Приватные черновики не создаются. При CAPTCHA, оплате, подписке, проверке личности, прав или неизвестной форме автоматизация останавливается. После передачи файлов неясный результат помечается «Проверить результат» и не повторяется автоматически — это защита от дублей.

Монетизация запускается отдельным этапом только для опубликованных треков, с заполненными данными и личным подтверждением прав пользователя. «Отправлено на проверку» не означает, что SoundCloud уже одобрил монетизацию.

## ACE-Step и память

В настройках укажи корневую папку ACE-Step 1.5. Она считается готовой, только если найдены `acestep/acestep_v15_pipeline.py` и Python из `.venv`.

- MacBook: Apple Silicon, batch 1.
- Windows: RTX 4060 8 ГБ, PyTorch, Turbo, batch 1, CPU offload.
- «Быстрее»: ACE-Step не перезапускается между треками, но модели остаются в памяти до конца очереди.
- «Экономия памяти»: сервис перезапускается между треками. Это медленнее, зато память освобождается.

После последнего трека принадлежащий Factory процесс ACE-Step выключается в обоих режимах. Модели ACE-Step не входят в сборку.

## JSON

```json
[
  {
    "release_title": "Amber Interstate",
    "target_account": "bos-423483424",
    "caption": "Original modern country pop instrumental, warm electric guitar, steady drums, memorable hook, 108 BPM",
    "lyrics": "[Instrumental]",
    "vocal_language": "unknown",
    "duration": 165,
    "bpm": 108,
    "key_scale": "A major"
  }
]
```

Для английского вокала укажи `vocal_language: "en"` и собственный текст в `lyrics`.

## Перенос на Windows

В «Настройки» → «Сохранить копию» экспортируются библиотека, WAV, названия и назначения. На Windows восстанови JSON копии через «Восстановить». Локальный путь ACE-Step, cookies, пароли и подтверждение прав не переносятся.

Для нового чата Codex на Windows приложи `WINDOWS-CODEX-PROMPT.txt`. Технический контекст находится в `AGENTS.md` и `WINDOWS-CODEX-HANDOFF.md`.

## Проверка исходников

```powershell
npm install
npm test
npm run build:windows
```

Автоматические тесты не публикуют реальные треки. Сборка Windows на macOS не доказывает работу CUDA, драйвера, ACE-Step или Chrome на целевом компьютере — там нужен отдельный smoke-тест без публикации.
